----------------------------------------------------
1. AUTHENTICATION  (/api/auth)
----------------------------------------------------

POST   /api/auth/register    → Register a new user
POST   /api/auth/login       → Login and get JWT token
GET    /api/auth/me          → Get current user info [REQUIRES TOKEN]

Register Body:
{
  "username": "John Doe",
  "email": "john@example.com",
  "password": "secret123",
  "role": "user"         // "user" or "admin"
}

Login Body:
{
  "email": "john@example.com",
  "password": "secret123"
}

Login Response: returns JWT token
Use as: Authorization: Bearer <token>

User Fields:
- id, username, email, password (hashed), role, created_at, updated_at

----------------------------------------------------
2. RESTAURANTS  (/api/restaurants)
----------------------------------------------------

GET    /api/restaurants          → Get all restaurants (public)
GET    /api/restaurants/:id      → Get restaurant by ID (public)
POST   /api/restaurants          → Create restaurant [ADMIN]
PUT    /api/restaurants/:id      → Update restaurant [ADMIN]
DELETE /api/restaurants/:id      → Delete restaurant [ADMIN]

Query Filters for GET all:
  ?location=   → partial match (case-insensitive)
  ?is_open=    → true / false
  ?limit=      → records per page
  ?page=       → page number
  ?offset=     → manual offset

Paginated Response:
{
  "total": 50,
  "limit": 10,
  "offset": 0,
  "page": 1,
  "data": [...]
}

Restaurant Fields:
- id
- name              (required)
- description
- disclaimer
- location          (required)
- phone_number      (required)
- logo_url          (image URL)
- menu_images       (array of image URLs, stored as JSONB)
- opening_time      (e.g. "09:00:00")
- closing_time      (e.g. "22:00:00")
- is_open           (boolean, default: true)
- is_verified       (boolean, default: false)
- average_cost_for_one (integer, INR)
- created_at
- updated_at

----------------------------------------------------
8. ADMIN ACCESS & SECURITY
----------------------------------------------------

Admin routes require one of the following secure credentials:
  Option A: Cryptographically signed JWT token where role = "admin"
            Header: Authorization: Bearer <token>
            (Recommended - obtained via login)

  Option B: Direct Admin Secret Key validation matching the server's ADMIN_SECRET_KEY
            Header: Authorization: Bearer <ADMIN_SECRET_KEY>
            (Used for background services and scripts)

⚠️ Note: The insecure "x-role: admin" bypass header has been completely removed.
In production, default fallback strings for secrets are blocked.

----------------------------------------------------
8.5 RATE LIMITING & SECURITY SHIELDS
----------------------------------------------------

To protect against brute-force and DDoS attacks, rate limiting is active:
  - Auth Endpoints (/api/auth/*): Max 15 requests per 15 minutes per IP.
  - General API Endpoints (/api/*): Max 100 requests per 15 minutes per IP.
  - Security Headers: Helmet middleware is active to prevent Clickjacking, MIME sniffing, and XSS.

To create an admin: register with role: "admin"
